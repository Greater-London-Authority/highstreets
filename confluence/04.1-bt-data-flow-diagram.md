## 🔄 Processing Steps Detail

### 1. **API Data Ingestion**
- **Hex 3-hourly**: `get_hex_data(start_date, end_date)` → Transform with `HexTransform.transform_data()`
- **MSOA Hourly**: `get_msoa_data(start_date, end_date)` → Transform with `MsoaTransform.raw_msoa_transform_data()`
- **LSOA Hourly**: `get_lsoa_data(start_date, end_date)` → Transform with `LsoaTransform.raw_lsoa_transform_data()`
- **Daily Aggregated**: `get_bt_daily_aggregate_customer_shapes()` → Transform with `DailyTransform.raw_bt_daily_preprocess_data()`

### 2. **Data Transformation Logic**
- **Population Calculation**: `worker = total_volume * worker_percentage / 100`
- **Visitor Derivation**: `visitor = total_volume - (worker + resident)`
- **Visitor Quality Check**: Negative visitor values are automatically set to 0 for data integrity
- **Time Mapping**: Convert API time indicators to standard format (e.g., "09AM-11AM" → "09-12")
- **ID Handling**: Remove "L" prefix from hex IDs for backward compatibility

### 3. **Spatial Aggregation**
- **SQL-based Processing**: Uses `fetch_and_transform_hex_data()` with SQL queries
- **Lookup JOINs**: Hex grid cells mapped to boundary areas via spatial lookup tables
- **Aggregation**: SUM volumes, AVERAGE loyalty/dwell time by boundary and time period

### 4. **Key SQL Queries**
- `hex_hs_transform_query.sql` - Highstreet aggregation
- `hex_tc_transform_query.sql` - Town Centre aggregation  
- `hex_bid_transform_query.sql` - BID aggregation
- `hex_bespoke_transform_query.sql` - Bespoke area aggregation
- `hex_all_layer_concat_query.sql` - UNION consolidation

### 5. **Output Formats**
- **Individual Boundary Files**: Exported to S3 by boundary type
- **Consolidated Analysis**: Single table with layer identifier for cross-boundary analysis
- **Sublicense Exports**: Filtered datasets for specific partners (Colliers, Fitzrovia, etc.)
- **London Datastore**: Automated uploads for public data access

## 📋 Column Specifications

### Raw Data Columns
- **Count Fields**: `resident`, `visitor`, `worker` (INTEGER)
- **Quality Metrics**: `loyalty_percentage`, `dwell_time` (FLOAT)
- **Identifiers**: `hex_id`/`msoa_id`/`lsoa_id`, `count_date`, `hours`/`hour`
- **Daily Specific**: `poi_id`, `poi_uid`, `poi_name`, `poi_type`, `time_indicator`

### Aggregated Columns
- **Spatial**: `x`, `y`, `borough` (coordinate and location info)
- **Averaged Metrics**: `ave_loyalty_percentage`, `ave_dwell_time`
- **Consolidated**: `id`, `name`, `layer` (standardized across all boundaries)

### Processing Notes
- **IDE Values**: Replaced with NULL (BT's suppression indicator)
- **Visitor Quality**: Negative visitor counts automatically adjusted to 0
- **Data Types**: Proper conversion to Int64 for nullable integers
- **Time Zones**: All dates in UTC, converted from API responses
- **Partitioning**: Monthly partitioning on `count_date` for large tables
