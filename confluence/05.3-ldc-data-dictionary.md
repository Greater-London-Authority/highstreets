# LDC Premises Data Dictionary

## Overview

This page provides column-level documentation for all LDC premises tables in PostgreSQL and the S3 Parquet archives. For architecture context, see [LDC Premises Data Source](05-ldc-premises-data-source.md).

---

## PostgreSQL Tables

### Schema: `gisapdata`

---

### ldc_premises_raw

**Purpose**: Accumulated, deduplicated working dataset. Holds all historical records from initial load plus monthly Snowflake upserts. This is the single source of truth -- equivalent to the legacy `all_biz_raw.csv` but persistent and append only.

**Row Count**: ~1.68M+ (grows monthly as new businesses open)
**Primary Key**: `(tenant_id, premises_id, date_create)` -- composite, supports upsert
**Partitioning**: None (full-table scans during transformation are acceptable at current scale)

#### Primary Key Columns

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `tenant_id` | `BIGINT` | NOT NULL | LDC unique identifier for each tenancy/business instance. Stable across renames. |
| `premises_id` | `BIGINT` | NOT NULL | LDC unique identifier for physical property location. Stable unless property splits/merges. |
| `date_create` | `TIMESTAMP` | NOT NULL | Date when tenancy/business started at this location. Immutable once set by LDC. |

#### Core Business Columns

| Column | Type | Nullable | Description | Example Values |
|--------|------|----------|-------------|----------------|
| `tenant` | `VARCHAR(500)` | NULL | Trading name of the business | Any business name or `Vacant Property` |
| `tenant_status` | `VARCHAR(50)` | NULL | Current lifecycle status | `Live`, `Closed`, `Vacant`, `Demolished` |
| `premises_status` | `VARCHAR(50)` | NULL | Status of the physical property | `Live`, `Vacant`, `Demolished`, `Merged`, `Split` |
| `category` | `VARCHAR(200)` | NULL | Second-level business classification (44+ values) | `Bakers`, `Cafes & Fast Food`, `Fashion & General Clothing`, `Restaurants`, `Estate Agents & Auctioneers` |

### ldc_premises_clean

**Purpose**: Transformed, analyst-facing output. Produced by `LdcPremisesTransform` from the full raw table. Refreshed monthly via TRUNCATE + full reload.

**Row Count**: ~1.66M (slightly fewer than raw due to deduplication and date-merge logic)
**Primary Key**: `id` (`BIGSERIAL` surrogate) -- accommodates rare SWS duplicates on `(tenant_id, premises_id, date_create)`
**Refresh Strategy**: Full TRUNCATE + INSERT each monthly run

| Column | Type | Nullable | Description | Transform Logic |
|--------|------|----------|-------------|-----------------|
| `id` | `BIGSERIAL` | NOT NULL | Surrogate auto-increment PK | Generated by PostgreSQL |

### ldc_premises_staging

**Purpose**: Temporary UNLOGGED table for upsert operations. Schema mirrors `ldc_premises_raw`. Truncated before each use and populated with the current Snowflake batch. Used as the source for `INSERT...ON CONFLICT`.

**Row Count**: Transient (~895K during upsert, then truncated)
**Primary Key**: Mirrors `ldc_premises_raw`
**Table Properties**: `UNLOGGED` (no WAL writes for faster bulk inserts; data loss acceptable since it's transient)

Created via:
```sql
CREATE UNLOGGED TABLE ldc_premises_staging (
    LIKE ldc_premises_raw INCLUDING ALL
);
```

## S3 Parquet Archives

### snowflake_snapshots (162 columns)

**Path**: `s3://hsds-data/ldc/snowflake_snapshots/year=YYYY/month=MM/current.parquet`
**Partitioning**: Hive-style by `year` and `month`
**Schema Source**: Determined by Snowflake query output at time of fetch
**Columns**: Full 162-column Snowflake schema, exactly as received (no transformation)

This archive preserves the complete LDC schema including columns not used in the PostgreSQL pipeline (e.g., detailed VOA fields, planning data, demographic overlays). Column names and types follow Snowflake conventions.

### initial_load (195 columns)

**Path**: `s3://hsds-data/ldc/initial_load/current.parquet`
**Partitioning**: None (single file)
**Schema Source**: Union of Historic Excel (195 cols) + Snowflake (162 cols) + Archived CSVs

One-time bootstrap archive. Contains the complete dataset used for initial load including all 195 columns from the Excel file (superset of Snowflake's 162). Written via `archive_to_s3_parquet(partition_by_month=False)` which produces `current.parquet` at the path root.

### clean_archives (38 columns)

**Path**: `s3://hsds-data/ldc/clean_archives/year=YYYY/month=MM/current.parquet`
**Partitioning**: Hive-style by `year` and `month`
**Schema**: Matches `ldc_premises_clean` table (38 columns, see above)

Monthly snapshot of the transformed output for audit trail and point-in-time comparison.

## Data Type Decisions

Several PostgreSQL types differ from naive pandas-to-SQL mappings. These were deliberate choices based on observed data:

| Column(s) | Naive Type | Chosen Type | Reason |
|-----------|-----------|-------------|--------|
| `flag_independent`, `flag_concession`, `flag_field_researched`, `flag_area_sm_modelled` | `BOOLEAN` | `SMALLINT` | Pandas reads CSV values as `float64` (0.0, 1.0, NaN). `BOOLEAN` rejects float/NaN. `SMALLINT` safely stores 0/1/NULL. |
| `premises_previous_id` | `BIGINT` | `TEXT` | Values contain structured merge references like `"52242964 Merged into 53133438; "`, not plain integers. |
| `geography_id`, `geography_large_id` | `INTEGER` | `BIGINT` | Some IDs exceed `INTEGER` range (~2.1B). `BIGINT` provides headroom. |
| `date_create`, `date_close`, etc. | `DATE` | `TIMESTAMP` | Preserves time component where present in source. `TIMESTAMP` sorts and compares correctly. |

## Glossary

| Term | Definition |
|------|------------|
| **Tenancy** | A specific business occupying a specific premises during a specific period. One row in the dataset. |
| **Premises** | A physical commercial property address. Identified by `premises_id`. |
| **SWS** | Store-Within-Store. A concession operating inside another business (e.g. a Clinique counter inside Boots). Has `tenant_care_of` set. |
| **Gap problem** | The period between the end of the historic Excel and the Snowflake rolling window where closed businesses disappear from both sources. |
| **Source priority** | `live > historic > archived`. When duplicate records exist across sources, the live (Snowflake) version is preferred. |
| **Row hash** | Hash of all working columns (via `pd.util.hash_pandas_object`, 32-bit hex). Used to detect whether a record has materially changed since last ingestion. |
| **UPRN** | Unique Property Reference Number. UK government standard for identifying addressable locations. |
| **VOA** | Valuation Office Agency. Government body that assigns rateable values to commercial properties. |
