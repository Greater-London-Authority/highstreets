## 🔄 Processing Steps Detail

### 1. **3-hourly Pipeline**
- **Raw Data**: `mcard_3hourly_latest_data_read()` → `preprocess_mcard_data()`
- **CPI Adjustment**: `load_cpi_data_to_postgres()` → `adjust_mcard_data_sql()`
- **Boundary Aggregation**: `fetch_and_transform_mcard_data()` with quad lookup JOINs
- **Consolidation**: `concat_and_load_all_mcard_quad_layers()`

### 2. **Weekly Pipeline - Raw Processing**
- **File Ingestion**: `process_mcard_raw_files()` → Raw table with file metadata
- **Data Cleaning**: `clean_and_process_data()` → Complete missing combinations
- **Incremental Staging**: `incremental_refresh_mcard_stg_18_zoom()` → Only new data

### 3. **Weekly Pipeline - Adjustment Factor Generation**
- **Inner/Outer Aggregation**: `get_inner_outer_weekly_summary()` 
- **Spending Pulse Integration**: `format_and_update_spending_pulse()`
- **Factor Calculation**: `create_adjustment_factor()` with rolling averages
- **Market Correction**: Cash-to-card shift + Mastercard market share

### 4. **Weekly Pipeline - Boundary Aggregation**
- **SQL Queries**: Layer-specific aggregation queries (e.g., `highstreet_weekly_query.sql`)
- **Market Adjustment**: `mcard_adjust_weekly()` applies adjustment factors
- **CPI Adjustment**: Sector-specific inflation correction
- **Sector Breakdown**: Weekday/weekend × Retail/Eating/Apparel

### 5. **Consolidation & YoY**
- **Layer Union**: `concat_and_load_all_mcard_weekly_txn_layers()`
- **YoY Calculation**: `calculate_yoy_growth_compared_to_2019()` 
- **YoY Union**: `concat_and_load_all_mcard_weekly_yoy_layers()`

## 📋 Column Specifications

### Raw Data Columns
- **3-hourly**: `quad_id`, `count_date`, `hours`, `txn_amt`, `txn_cnt`, `avg_spend_amt`
- **Weekly**: `yr`, `wk`, `quad_id`, `industry`, `segment`, `weekday_weekend`, `file_name`
- **Transactions**: `txn_amt`, `txn_cnt`, `acct_cnt`, `avg_ticket`, `avg_freq`

### Staging Columns
- **Clean**: Filtered to specific industries (Total Retail, Total Apparel, Eating Places)
- **Staging**: Optimized for incremental processing with proper data types
- **Pre-adjustment**: Aggregated by Inner/Outer London for factor generation

### Adjustment Columns
- **Market Factors**: `adjustment_factor_retail`, `adjustment_factor_eating`, `adjustment_factor_apparel`
- **CPI Data**: `yr`, `month`, `aggregate`, `cpi_index`
- **Application**: Applied per sector and geography

### Weekly Output Columns
- **Sector Breakdown**: `txn_amt_wd_retail`, `txn_amt_we_retail`, etc.
- **Transaction Counts**: `txn_cnt_wd_retail`, `txn_cnt_we_retail`, etc.
- **Adjusted Versions**: `*_adj` columns for inflation-adjusted values
- **YoY Metrics**: `yoy_*` columns for growth rates

### Processing Notes
- **Industry Filtering**: Total Retail, Total Apparel, Eating Places only
- **Weekday/Weekend**: Separate processing for different spending patterns
- **Geographic Hierarchies**: Quad → Boundary via spatial lookup tables
- **Temporal Aggregation**: ISO week standards with proper date handling
- **Performance Optimization**: Unlogged temp tables, bulk inserts, index optimization
